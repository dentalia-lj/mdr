Scheduler

{% call ui.intro("The cron producer: what it fires, when it last fired, and what the weekly report said.") %} The crons run on the queue: one perpetual, self-deferring scheduler.tick job per cron, claimed by the worker like any other job. They run no business logic — each tick reads state and enqueues the next stage's job(s) — and record one row per (cron, period) in scheduler_run so a restart cannot re-fire a period that already ran. That ledger is what this page reads.

A daily cron writes the ledger once a day however often it ticks, so freshness alone cannot prove the process is alive. The verdict below is whether the current period is recorded: ok it is · due it is not yet, but the previous run is recent · stale nothing for more than two of this cron's own periods · never this cron has no ledger row at all.

Emission flags are read from this container's SCHEDULER_* environment, which Compose fills from the same .env as the scheduler's own.
