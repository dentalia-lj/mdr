API reference

Three kinds of caller reach this application and only one has a browser. What a caller may reach depends on the credential it carries; the policy is one table, in web/access.py, and it is default-deny.

Credentials

ClassHow it authenticatesWho
staff HTTP Basic, at the Caddy proxy Us. This UI and everything in it.
service X-API-Key header The webstore backend (Erpium). Calls server-side. Since 2026-11-23 it reaches only the webstore routes, always in the customer view, and hands its customers files through five-minute download links (below). A valid key on any other /api/ route gets 403 here, and plain 404 Not found on api.cw.dentalia.si, where Caddy answers first.
bc ?k= in the query string A Business Central item-card hyperlink. BC builds links by string concatenation, so it cannot compute a signature — hence one shared static key rather than a per-item one. 
# staff — through the proxy, as your browser already does
curl -u "$DENTALIA_WEB_USER:$PASSWORD" https://HOST/items

# service — the webshop backend
curl -H "X-API-Key: $WEB_API_KEYS" https://HOST/api/items/{{ example_ref or 'ITEM' }}/documents

# bc — the item-card link
curl "https://HOST/item/{{ example_ref or 'ITEM' }}?k=$WEB_BC_LINK_KEY"

The webstore: what a key gets

Full design: docs/superpowers/specs/2026-11-23-webshop-api-design.md.

  • Routes: /api/manufacturers, /api/manufacturers/{id}, /api/manufacturers/{id}/documents, /api/items/{item_ref}/documents, /api/items/documents, /api/documents/{doc_id}/link. Nothing else.
  • Always the customer view. view=full is ignored; include_unlinked and include_superseded answer 400.
  • Only documents a clinic may be shown: published, current for the item, and not past their legal expiry. valid_to is that legal expiry, so a class I DoC with no stated date shows null.
  • Files on click: the page links to the webstore's own URL. On a click its server calls /api/documents/{doc_id}/link and answers the browser with a 302 to the returned url (/d/…, valid 5 minutes, no key in it). Never put that url or the key into a page.
  • Limits: 429 with Retry-After past 1,200 calls a minute per key, or past 30 distinct documents a minute / 100 a day per customer address on /d/.
# on the customer's click, server-side
curl -H "X-API-Key: $WEB_API_KEYS" https://HOST/api/documents/{{ example_doc_id or 'DOC_ID' }}/link
# {"url": "https://HOST/d/<doc_id>.<exp>.<sig>", "expires_at": "…"}

GET /api/documents/{doc_id}/link

service · staff — a signed download link for one document, valid WEB_DOWNLOAD_LINK_TTL_S (5 minutes). 404 when the document is not one the webstore may show, or when WEB_DOWNLOAD_LINK_SECRET is empty.

GET /d/{token}

anyone — the token is the credential. Serves the PDF inline after checking, again, that the document may be shown. 410 expired or altered, 404 no longer visible, 429 past the per-address limit.

Field notes

  • valid_to is the effective expiry, not the document's raw validity_to: a DoC that cites a certificate reports the certificate's date here.
  • expiry_basis says which rule produced it — stated, inherited, staleness, or null. staleness is a five-year review horizon Dentalia chose, not a legal expiry, which is why view=customer withholds it.
  • name is derived, never stored, and degrades gracefully: no manufacturer evidence means it starts at the type, no expiry means no "valid to" clause. Never a literal "None DoC".
  • url is constructed, never read from the database. archive_url is a storage handle, not a link.
  • mfr_ref is nullable. Null is a known data state, not an error.

?include_superseded=true

By default an item returns its current documents per type: one, or several when they carry the same issue date. This flag returns every published document linked to the item, including the older ones that are history for it. Works on /api/items/{item_ref}/documents and on the batch endpoint, where it applies to every entry. Flagged rows come newest first by issue date, undated documents last.

Flagged documents carry three extra fields, and only when the flag is on: current (true when the document answers for this item), status (production or superseded; not the same thing as current) and superseded_by (the doc_id this document was filed behind, null otherwise). Those doc_ids are fetchable: /api/documents/{doc_id} serves superseded documents too.

  • Not available with view=customer — the combination returns 400. A history row is paperwork that does not answer for the item; a clinic must never be shown it as coverage.
  • Not reachable from the BC card. /item/{item_ref} ignores it.
  • Staged, rejected and filed documents stay invisible, and so does any document whose link to the item is not production. The flag widens the set to older published documents and nothing else.

Expired is not superseded. An expired document was never hidden — nothing here filters on expiry. Read valid_to and decide for yourself; you do not need this flag for that.

GET /item/{item_ref}/documents.zip

bc · staff — every production document for the item, one archive. The "papers" a client asks for on the phone are plural. 404 when the item has no reachable production documents — an empty archive is a worse answer than saying there is nothing.

GET /item/{item_ref}/documents/{doc_id}

bc · staff — one of the item's documents, the PDF the card's Open link serves on the BC key alone. Only a production document with a production link to that item; any other doc_id is a 404, like the rest of /item/*. Not open to an API key: the webstore uses /api/documents/{doc_id}/link.

GET /documents/{doc_id}/file

staff — the archived PDF, any status. Closed to API keys since 2026-11-23: by sequential id it opened the whole archive, staged and rejected documents included.

GET /api/documents/{doc_id}

staff — one production document and its complete evidence. Internal. Carries model_id, confidence and verbatim. Never render this to a customer. confidence is the model's own number, not calibrated; where two reads agreed on the value, each at least {{ "%.2f"|format(agreement_min) }}, it combines the two and the row names the second read in agreed_model_id and agreed_confidence, and it is 1.0 for a regulation its printed citation proves.{% if example_doc_id %} Try /api/documents/{{ example_doc_id }}.{% endif %}

GET /api/kpi

staff — the KPI board, the same numbers the status page shows. Top-level keys: coverage, match_basis, missing_mfr_ref, staging, manual_by_kind, dead_jobs, jobs_by_type_status, spend, and webshop (today's distinct documents linked per key fingerprint and the alert threshold, from process memory). Not rendered inline here: it measures ~478ms and this page is not worth half a second. Try it.

GET /api/items/documents?ref=…&ref=…

service · staff — several items in one call, for an order page. Repeat ref per item; takes view as above. Max {{ max_batch_refs }} refs, 400 beyond that or with none at all.

Entries come back in the order you asked for, and a ref this system has never mirrored is kept as a null-identity entry rather than dropped — you are drawing a row per order line and need to know which line has nothing, which a shorter array cannot tell you.

GET /api/manufacturers

service · staff — every manufacturer with its stable id and its production item and document counts. ?q= filters on name (staff: also on code). With an API key it is the webstore's tree: no BC codes, and only manufacturers with at least one document the webstore may show (published and not past its legal expiry).

GET /api/manufacturers/{id}

service · staff — one manufacturer's identity and production counts, addressed by the stable id from the list. The id survives a rename; the name does not. BC codes for staff only. 404 if the id is unknown. {% if example_manufacturer_id %}Try /api/manufacturers/{{ example_manufacturer_id }}.{% endif %}

Staff can also address a manufacturer by name: /api/manufacturers/by-name/{canonical_name}, with the same /documents and /items beneath it. Not open to an API key, and not "a number means an id": a canonical name can be a bare BC code such as 077.

GET /api/manufacturers/{id}/documents

service · staff — every production document reachable from any item of this manufacturer, deduped. That dedupe is the point: one ISO 13485 certificate can cover a whole line, and listing per item would return it hundreds of times and bury the handful that differ. Takes view.

?include_unlinked=true additionally returns documents bound to this manufacturer that reach it through no item at all — in the full view they carry match_basis of mfr-bound (view=customer drops that field, as it does everywhere). That set is large and is not coverage: a filed document is real, held and evidenced, and explicitly says we stock nothing it covers. Measured 2026-09-16, VOCO's documents endpoint returns 32 of the 283 documents held under that name; the other 251 reach no stocked item. Off by default because returning them unannounced would change what your existing payload means.

Two knobs, two questions: view is the projection (which fields), include_unlinked is the row set (which documents). Same split as include_superseded above.

GET /api/manufacturers/{id}/items

staff only (since 2026-11-23: it is Dentalia's supplier map) — that manufacturer's items, each with its production document count. Paginated, and not optionally: ~16k items are mirrored today and ~100k is the target.

ParameterDefaultMeaning
page1 1-based. A page past the end returns an empty items and the real total, not an error.
per_page{{ default_per_page }} Capped at {{ max_per_page }}. Asking for more silently gets the cap — check per_page in the response.

Response carries page, per_page, total, pages and items.

GET /archive/{path}

staff only — serves the archive by path and is therefore walkable. A valid API key does not open it.

Status codes

CodeWhen
200Including an item with no documents, and an item this system has never mirrored — identity fields come back null and documents is empty.
401Missing or wrong X-API-Key on /api/*. A service caller deserves a diagnosable error.
403A caller reaching a path its class does not cover.
404Missing or wrong ?k= on /item/*. Deliberately not 403: a 403 would confirm the item exists. Expect this, do not report it as a bug.

What you can rely on

Responses are additive-only. A field may be appended; an existing field is never removed, renumbered, or repurposed to mean something new. Tolerate unknown fields, never missing ones.

Integration recipes

Business Central

A computed field on the item card. No round trip, nothing stored:

"https://HOST/item/" + "No." + "?k=" + LinkKey

URL-encode No. if your item numbers contain a slash.

Webshop

  1. Fetch server-side with X-API-Key and ?view=customer. (Which is why view=customer and include_superseded cannot be combined.)
  2. Render the document list in your own page, under your own login.
  3. Proxy the bytes from url under your own origin — do not hand our URL to the customer.

For an order page use the batch endpoint below — one call, not one per line.
