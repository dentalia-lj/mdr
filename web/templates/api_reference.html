API reference

Three kinds of caller reach this application and only one has a browser. What a caller may reach depends on the credential it carries; the policy is one table, in web/access.py, and it is default-deny.

Credentials

ClassHow it authenticatesWho
staff HTTP Basic, at the Caddy proxy Us. This UI and everything in it.
service X-API-Key header The webshop backend. Fetches server-side and relays to its own logged-in customers, which is why nothing here is public.
bc ?k= in the query string A Business Central item-card hyperlink. BC builds links by string concatenation, so it cannot compute a signature — hence one shared static key rather than a per-item one. 
# staff — through the proxy, as your browser already does
curl -u "$DENTALIA_WEB_USER:$PASSWORD" https://HOST/items

# service — the webshop backend
curl -H "X-API-Key: $WEB_API_KEYS" https://HOST/api/items/{{ example_ref or 'ITEM' }}/documents

# bc — the item-card link
curl "https://HOST/item/{{ example_ref or 'ITEM' }}?k=$WEB_BC_LINK_KEY"

Endpoints

{# ---------------------------------------------------------------- #}

GET /item/{item_ref}

bc · service · staff — one item and its production documents. This is the URL BC puts on the item card and the one a support rep sends a client to.

ParameterInDefaultMeaning
item_refpath— Dentalia's own item number. May contain /; URL-encode it.
kquery— The shared BC link key. Required unless you are staff or service.
formatquery(unset) json forces JSON. Otherwise Accept: application/json decides, and a browser gets HTML.
viewqueryfull customer narrows it to what a clinic may see.

One URL, two renderings. A rep clicking from BC gets a page with download buttons. The webshop asking with Accept: application/json gets the payload below. The ?format=json override exists because BC's HTTP client is not guaranteed to send a useful Accept, and a rep must never land on a raw JSON blob.

Field notes

  • valid_to is the effective expiry, not the document's raw validity_to: a DoC that cites a certificate reports the certificate's date here.
  • expiry_basis says which rule produced it — stated, inherited, staleness, or null. staleness is a five-year review horizon Dentalia chose, not a legal expiry, which is why view=customer withholds it.
  • name is derived, never stored, and degrades gracefully: no manufacturer evidence means it starts at the type, no expiry means no "valid to" clause. Never a literal "None DoC".
  • url is constructed, never read from the database. archive_url is a storage handle, not a link.
  • mfr_ref is nullable. Null is a known data state, not an error.

?include_superseded=true

Adds the documents an item's current paperwork replaced — the supersession chain. Off by default, so nothing you already call changes. Works on /api/items/{item_ref}/documents and on the batch endpoint, where it applies to every entry.

Flagged documents carry two extra fields, and only when the flag is on: status (production or superseded) and superseded_by (the doc_id that replaced this one, null on a current document). Those doc_ids are fetchable: /api/documents/{doc_id} serves superseded documents too.

  • Not available with view=customer — the combination returns 400. A superseded document is the paperwork we replaced; a clinic must never be shown it as coverage.
  • Not reachable from the BC card. /item/{item_ref} ignores it.
  • Staged, rejected and filed documents stay invisible, and so does any document whose link to the item is not production. The flag widens the document status filter and nothing else.

Expired is not superseded. An expired document was never hidden — nothing here filters on expiry. Read valid_to and decide for yourself; you do not need this flag for that.

{# ---------------------------------------------------------------- #}

GET /item/{item_ref}/documents.zip

bc · service · staff — every production document for the item, one archive. The "papers" a client asks for on the phone are plural. 404 when the item has no reachable production documents — an empty archive is a worse answer than saying there is nothing.

GET /documents/{doc_id}/file

service · staff — the archived PDF. This is the supported way to get bytes; the webshop relays them under its own origin.

GET /api/documents/{doc_id}

service · staff — one production document and its complete evidence. Internal. Carries model_id, confidence and verbatim. Never render this to a customer.{% if example_doc_id %} Try /api/documents/{{ example_doc_id }}.{% endif %}

GET /api/kpi

service · staff — the KPI board, the same numbers the status page shows. Top-level keys: coverage, match_basis, missing_mfr_ref, staging, manual_by_kind, dead_jobs, jobs_by_type_status, spend. Not rendered inline here: it measures ~478ms and this page is not worth half a second. Try it.

GET /api/items/documents?ref=…&ref=…

service · staff — several items in one call, for an order page. Repeat ref per item; takes view as above. Max {{ max_batch_refs }} refs, 400 beyond that or with none at all.

Entries come back in the order you asked for, and a ref this system has never mirrored is kept as a null-identity entry rather than dropped — you are drawing a row per order line and need to know which line has nothing, which a shorter array cannot tell you.

GET /api/manufacturers

service · staff — every manufacturer with its BC codes and its production item and document counts. ?q= filters on name or code.

GET /api/manufacturers/{canonical_name}

service · staff — one manufacturer's identity, its BC codes, and production counts. 404 if the canonical name is unknown. {% if example_manufacturer %}Try /api/manufacturers/{{ example_manufacturer }}.{% endif %}

GET /api/manufacturers/{canonical_name}/documents

service · staff — every production document reachable from any item of this manufacturer, deduped. That dedupe is the point: one ISO 13485 certificate can cover a whole line, and listing per item would return it hundreds of times and bury the handful that differ. Takes view.

?include_unlinked=true additionally returns documents bound to this manufacturer that reach it through no item at all — in the full view they carry match_basis of mfr-bound (view=customer drops that field, as it does everywhere). That set is large and is not coverage: a filed document is real, held and evidenced, and explicitly says we stock nothing it covers. Measured 2026-09-16, /api/manufacturers/VOCO/documents returns 32 of the 283 documents held under that name; the other 251 reach no stocked item. Off by default because returning them unannounced would change what your existing payload means.

Two knobs, two questions: view is the projection (which fields), include_unlinked is the row set (which documents). Same split as include_superseded above.

GET /api/manufacturers/{canonical_name}/items

service · staff — that manufacturer's items, each with its production document count. Paginated, and not optionally: ~16k items are mirrored today and ~100k is the target.

ParameterDefaultMeaning
page1 1-based. A page past the end returns an empty items and the real total, not an error.
per_page{{ default_per_page }} Capped at {{ max_per_page }}. Asking for more silently gets the cap — check per_page in the response.

Response carries page, per_page, total, pages and items.

GET /archive/{path}

staff only — serves the archive by path and is therefore walkable. A valid API key does not open it.

Status codes

CodeWhen
200Including an item with no documents, and an item this system has never mirrored — identity fields come back null and documents is empty.
401Missing or wrong X-API-Key on /api/*. A service caller deserves a diagnosable error.
403A caller reaching a path its class does not cover.
404Missing or wrong ?k= on /item/*. Deliberately not 403: a 403 would confirm the item exists. Expect this, do not report it as a bug.

What you can rely on

Responses are additive-only. A field may be appended; an existing field is never removed, renumbered, or repurposed to mean something new. Tolerate unknown fields, never missing ones.

Integration recipes

Business Central

A computed field on the item card. No round trip, nothing stored:

"https://HOST/item/" + "No." + "?k=" + LinkKey

URL-encode No. if your item numbers contain a slash.

Webshop

  1. Fetch server-side with X-API-Key and ?view=customer. (Which is why view=customer and include_superseded cannot be combined.)
  2. Render the document list in your own page, under your own login.
  3. Proxy the bytes from url under your own origin — do not hand our URL to the customer.

For an order page use the batch endpoint below — one call, not one per line.
