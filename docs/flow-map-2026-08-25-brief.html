The topology is the enqueue graph: 33 queue.enqueue call sites, 22 distinct dedupe-key shapes, all through app/queue.py. Dedupe is scoped to active jobs only, so a terminal job never blocks a re-enqueue. The shipped stack holds discovery (DISCOVER_HOLD defaults true in compose, false in code): the corpus is mined first, discovery runs later against a registry that knows what it already has.

3The two states that decide what a consumer sees

stateDiagram-v2
  direction LR
  [*] --> staged: below HIGH or capped by a flag
  [*] --> production: HIGH + ref_gate + nothing gating
  [*] --> superseded: older, all four guards pass
  [*] --> filed: read + attributed, covers nothing we sell
  staged --> production: approve / bind
  staged --> rejected: reject
  production --> superseded: a newer doc supersedes it

stateDiagram-v2
  direction LR
  [*] --> staged: any basis
  [*] --> production: trusted basis + doc production + HIGH
  staged --> production: approve, or confirm-link
  staged --> staged: name-family / fetch-context / ref-catalogue, forever
  staged --> retracted: current rev no longer claims it
  staged --> rejected: reject cascade, or reject-link
  production --> rejected: reject cascades every link
  rejected --> staged: reopen-link, a person only

A document is visible for an item only when both the document and that item's link are production. The two are decided separately and a different number of times: once per document, once per (document, item) pair. production and rejected are sticky against a re-proposing machine candidate, so nothing resurrects coverage a human refused; only a person moves a link out of rejected. Live: 769 documents (443 filed, 194 production, 126 staged, 4 superseded, 2 rejected) carrying 8.563 links (7.927 production, 357 retracted, 279 staged, all 279 on a trusted basis and waiting on their document rather than on a link decision).
