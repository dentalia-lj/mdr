## Handlers (one module per queue tag)

Registered in `app/handlers/__init__.py`'s `HANDLERS` dict; `noop.py` provides placeholders for every tag via `setdefault`, so registration order cannot clobber a real handler (it used to `register()` unconditionally, which put `extract.doc` and `backfill.scan` on the placeholder whenever noop imported second). **A placeholder raises `UnimplementedStage` and dead-letters** rather than finishing `done` — **every tag now has a real handler** (verified against `HANDLERS` on 2026-09-04; `playbook.reonboard` was the last, and its probe branch landed with S2.2 in `app/handlers/playbook_probe.py`. Its OTHER half, the failure-monitor reonboard path, still raises — but from inside the real handler, for the same reason. Earlier: `email.request`/`email.reminder` shipped with S2.4 on 2026-08-20, `eudamed.sync` on 2026-08-25, and `vendor.import` arrived with its handler already written). The placeholder module stays: it is what a NEW tag gets between the migration that adds it and the handler that serves it, and that gap is exactly when a silent no-op would do the damage.
